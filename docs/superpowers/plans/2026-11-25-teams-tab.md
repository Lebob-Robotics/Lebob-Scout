# Teams Tab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Teams tab in the scout app showing scouting status, team profiles, a coverage grid and a scouts list, with the sums done by Foundry functions that Workshop can also call.

**Architecture:** A new TypeScript v2 functions repository in the "Lebob Scout App" Foundry project. The sums are pure modules with tests (`src/teams/`); three thin published functions load the event's objects and call them. The app calls one function, `teamsTab`, when the tab opens and draws the result. Search, filters, open rows and the phone's waiting count stay in the app.

**Tech Stack:** Foundry TypeScript v2 functions (`@osdk/client`, `@osdk/functions`), the repository's own test runner (found in Task 1). App as before: React, TypeScript, Vite, Vitest, plain CSS, `@lebob-scout/sdk` (new version with the functions).

**Spec:** `docs/superpowers/specs/2026-11-25-teams-tab-design.md`. It builds on the two earlier designs in the same folder.

**Reference files:** `.superpowers/teams-tab-functions-recon.md` (how Foundry functions are built, published and called, with doc page paths and an UNCONFIRMED list). `reference/lebob-scout-site.html` lines 350 to 366, 913 to 991, 1041 to 1064 (the old tab) and 1432 to 1438 (the cycle rule).

**Branch:** `teams-tab` in the app repo, cut from `scout-polish` once that pass is deployed. The functions repository is its own git repository with Foundry as origin, cloned to `scout-functions/` in the repo root and git-ignored there.

## Global Constraints

- Everything in the first two plans' Global Constraints still holds for the app: the look, 48 px tap targets, the data-safety rules, no request to any site other than Foundry.
- `FOUNDRY_TOKEN` is loaded only inside the command that needs it and never written to a file or printed. `git diff --cached | grep -c eyJ` prints 0 before every commit, in both repositories.
- Foundry: no change to any object type, link type or action type. Nothing is deleted. Nothing in the old project `/Lebob-7db4f1/LebobFTCScouting` is changed. The hosted site stays not public.
- The sums exist once, in the functions repository. The app does no arithmetic on reports beyond counting, filtering and rounding for display.
- **Auto** is a tap with seconds below 30. Everything else is teleop.
- **Pieces scored** is the sum of counts on taps of kind `shoot`. Intake taps never add to it, whatever their count (older reports have 1 to 4).
- **Points for `ftc-2026`:** leave 3, auto park 5, teleop park 5, one piece scored `20 / 7.5`. Keyed by the report's `fieldKey`; an unknown key uses `ftc-2026`.
- **Two reports for one match:** every figure is averaged over that match's reports first, then over matches. On the map each of them counts for half.
- **A match** is identified by match type and match number. Reports are matched to the schedule by match type, match number and team number, never by uuid.
- **Played:** the match has an actual time, or its scheduled time is at or before now. If no match at the event has either time, a match is played when a report exists for a match of the same type with the same or a higher number.
- **Match label:** `Q` for qualification, `P` for playoff, then the number: `Q3`, `P1`.
- The map is never turned and never dimmed. Squares are as stored: A to F from the red wall, 1 to 6 from the top.
- A failed or slow function call never blocks Reports, New match, or the save queue.
- Prose in the app follows the existing screens: plain words, no exclamation marks.

## Review Focus

- Two scouts cover one robot in one match: the profile tiles, the map and the "matches" count must count that match once, and the coverage cell must show `×2`.
- An event where no match has a time: "played" falls back to the highest scouted number, and matches beyond it are "to come".
- A report typed by hand for a team that is not in that match, or for a match not in the schedule: it shows in that team's profile and in the stray counts, and breaks nothing.
- The function call fails, or takes 20 seconds: the tab shows Retry, and the scout can still open Reports and start a match.
- Reports with empty tap lists, tap lists of unequal length, no `startWallPos`, or intake counts of 1 to 4: no `NaN`, no crash, no piece counted from an intake.
